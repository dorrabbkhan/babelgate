## Main post

Every LLM gateway promises "any client on any model". babelgate's
promise is narrower: **the translator you can check** — a proxy that
translates between five API dialects (OpenAI Chat, Anthropic, Gemini,
Ollama, OpenAI Responses) and publishes the evidence: a compatibility
matrix generated from the test suite, a per-request inspector, signed
releases.

1.6 is about getting to that check in one command:

```bash
GEMINI_API_KEY=<free key from https://aistudio.google.com/apikey> \
  babelgate --preset claude-code --provider gemini-free
```

It prints two `export` lines for Claude Code (or the `config.toml`
block for Codex with `--preset codex`) — paste them and the client runs
on the preset's model, one that passed the real edit-task gate before
it was listed. "Free" means *per the provider's own docs on the
verification date* — `babelgate presets` prints the date and doc link
for each of the five free presets and the cheap one; nothing is
promised beyond what those docs say.

### What shipped

**Single-file binaries and one-command installers.** The whole gateway
— server and UI — is one executable per platform (Node SEA), built and
process-tested on its own release runner: a release ships only what its
tests passed on that platform. `brew install
dorrabbkhan/babelgate/babelgate`, `install.sh`, `install.ps1`, `npx
babelgate` and the Docker image all run the same CLI. Every binary is
cosign-signed; the installers check `SHA256SUMS` and verify the
signature when cosign is on PATH, and a mismatch aborts leaving nothing
behind — verification walkthrough: `SECURITY.md`.

**Free and cheap provider presets.** `--provider <name>` fills the
target type, base URL, key env var and output-token cap from the preset
registry — the key stays in the environment variable it already lives
in (`TARGET_API_KEY_ENV` names it; no secret is copied between
variables). Presets also carry the provider's known wire gaps (e.g.
DeepSeek's `json_schema` refusal is declared and downgraded with a
note, not silently stripped) and each row was verified against the
provider's own docs — the doc URL and date ship with the preset:
`src/config/provider-presets.ts`.

**A passive circuit breaker and an opt-in response cache.** Three
consecutive upstream failures open a provider's breaker for a 30 s
cool-down (doubling to 5 min); route planning skips it — and still
tries the first target when every provider is open, so the breaker
never refuses locally. The cache is exact-match, in memory, off by
default (`CACHE=on`): identical canonical requests to the same target
replay in the asking client's format, for CI runs and test suites.

**Reasoning, wider.** Anthropic's `between_tools` thinking decodes to
canonical effort instead of being dropped, and the `openrouter-free`
and `deepseek` presets pass Chat-format `reasoning_content` back
upstream — verified against each provider's reasoning docs. Failed
requests also reach the `/ui` inspector now, so a refused call shows
its translation stages instead of only a log line.

### Why it can be trusted

- The compatibility matrix (`docs/compatibility.md`) is generated by
  `npm run matrix` from the pair tests; CI regenerates it and fails on
  drift.
- A weekly job replays each new Claude Code and Codex release's
  recorded shapes through the gates and opens an issue on drift — the
  badge on the matrix is the last run.
- Release binaries and the container image are cosign-signed in CI;
  `SHA256SUMS` and a CycloneDX SBOM ship with every release.
- Every request is inspectable: `/ui` shows source → canonical →
  target, names every dropped field, and keeps bodies in memory only.

## r/LocalLLaMA variant

**Title:** babelgate 1.6 — run Claude Code / Codex on local or free
models, with the translations you can actually check

babelgate is a self-hosted proxy that translates between LLM API
formats (OpenAI, Anthropic, Gemini, Ollama, Responses) via a canonical
intermediate format. Point Claude Code or Codex at it and it runs on
whatever model you can reach — local Ollama models included.

1.6 is the "one command, free to start" release: signed single-file
binaries, `--provider` presets for the free tiers (Gemini, OpenRouter
`:free` models, Groq, NVIDIA NIM, Cerebras — each verified against the
provider's docs, date printed by `babelgate presets`), a `codex` client
preset, a passive circuit breaker for when a free tier hits its daily
cap mid-session, and an opt-in exact-match response cache for test
suites.

The check: `docs/compatibility.md` is generated from the pair tests (CI
fails on drift), a weekly job replays each new Claude Code/Codex
release through the gates, and the `/ui` inspector shows exactly what
each translation changed — including which fields were dropped, and now
failed requests too.

Honest caveat for local: the release gate passed on hosted models, not
on a capable local model — small local models call tools unreliably,
and a CPU-bound model can stall past the stream idle timeout. The known
limitations are in the README. Apache-2.0.

What `docs/research/2026-11-24-conformance-run.md` (and its `.shapes`
appendix) found, as raw material for the owner's decision:

- Gateways tested: babelgate (default and `reasoning_passback`
  opt-in), claude-code-router 3.1.6, free-claude-code v6.15.0
  (e8806fb608ac). Scenarios: thinking after a tool call, streamed
  tool-call arguments, multi-turn reasoning — Anthropic and Responses
  clients against Chat-only and Gemini upstreams.
- Live-confirmed `fail` cells (all-2xx exchanges, doc-cited rules,
  OpenRouter `deepseek/deepseek-v4.1-flash`, 2026-11-24):
  - `babelgate-default` (passback off): thinking-after-tool
    `{anthropic,responses}->openai` — turn-2 assistant message carried
    no reasoning field.
  - `ccr`: thinking-after-tool `{anthropic,responses}->openai` (no
    reasoning sent back) and multi-turn-reasoning
    `{anthropic,responses}->openai` (upstream response carried
    reasoning, client stream showed no reasoning block).
  - `free-claude-code`: multi-turn-reasoning `anthropic->openai` (3 of
    3 repeats) — emits an unsigned thinking block; signing is gated on
    a profile flag no custom-provider config can set (diagnosis in the
    report §Task 13g).
- `differs` observations (no cited doc requires the behaviour):
  `babelgate-default` multi-turn `{anthropic,responses}->openai`;
  `free-claude-code` multi-turn `responses->openai` (3 of 3) — history
  replay scope keeps `reasoning_content` only inside the
  tool-continuation window.
- Not confirmable this run: every `*->gemini` cell (Gemini 429/503);
  `streamed-tool-args:anthropic->openai` never ran live.
- babelgate with `reasoning_passback` passed every OpenRouter cell
  live; the `passback-tokens.ts` probe (provider Wafer) showed the live
  model consuming the sent-back reasoning (prompt_tokens 349 → 359).
- babelgate's own default has live-confirmed `fail` cells too — the
  `reasoning_passback` preset flag exists because plain Chat servers
  may reject the field. If these results ever go public, that
  symmetry is part of the honest telling.
