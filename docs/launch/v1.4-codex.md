# Codex on Gemini and Claude

*Draft launch post — babelgate v1.4. Owner reviews before publishing.*

OpenAI's Codex CLI is a strong coding agent — but it only speaks one wire
format, the Responses API, and until now that meant one vendor's models.
babelgate 1.4 removes that wall: point Codex at babelgate and run it on
Gemini 3.x, Claude, or any OpenAI-compatible backend, with streaming, tool
calls and structured output intact — or straight through to a
Responses-native upstream with routing, cost and observability added.

```toml
# ~/.codex/config.toml
model = "babelgate"
model_provider = "babelgate"
model_reasoning_effort = "medium"

[model_providers.babelgate]
base_url = "http://localhost:3000/v1"
wire_api = "responses"
env_key = "BABELGATE_KEY"
requires_openai_auth = false
```

## What shipped

**A fifth adapter.** The OpenAI Responses API joins OpenAI Chat, Anthropic,
Gemini and Ollama as a first-class format — `POST /v1/responses` works as a
client-facing source and `type: responses` as an upstream target. Codex is
just a client of it: there is no Codex-specific code path, so every other
Responses-speaking tool gets the same ride.

**Reasoning that survives the session.** Claude's signed thinking blocks and
Gemini's `thoughtSignature`s are carried inside the `reasoning` items Codex
already resends every turn (`reasoning.encrypted_content`), packed in a `bg1.`
envelope. On the next turn the same provider gets its own reasoning back,
bit-for-bit — and reasoning from provider X is never sent to provider Y,
tagged by origin and dropped with a note instead. Long sessions are bounded:
an envelope over 1 MB degrades to a visible note, not a failed request.

**Byte-preserving pass-through.** Route to a `type: responses` provider —
OpenRouter's Responses API, vLLM, Ollama's Responses endpoint, LM Studio,
Together, Groq, DeepSeek — and the request is relayed untouched except the
model name. You still get fallbacks before the first byte, usage and cost
accounting, tool-call diagnostics, and the inspector's pass-through view.
Codex's own encrypted reasoning goes back to the same upstream verbatim.

**Custom tools and structured output, everywhere.** Freeform tools like
`apply_patch` bridge to function tools and back losslessly — input that looks
like broken JSON is never "repaired". `json_schema` response formats map
natively to all five providers, forwarded unchanged: babelgate never strips a
schema keyword to make a target accept it.

**Same observability.** Every turn lands in the trace and usage store —
reasoning tokens included — shows up in the Requests feed, and opens in the
inspector with reasoning rendered as collapsible blocks and signatures shown
by size and origin, never by content.

- **Gate B** — Codex on `anthropic/claude-haiku-4.5`, thinking on
- **Gate C** — Codex on `qwen/qwen3-coder` via OpenRouter's Responses API,
  full pass-through

…plus a 5×5 format pair matrix in CI. Results and model versions live in
`docs/decisions.md`.

## Honest edges

babelgate is stateless: `previous_response_id`, `store: true` and
conversations get a clean 400 (Codex never sends them over HTTP). OpenAI's
built-in tools — `web_search`, `code_interpreter`, MCP — are forwarded on
pass-through but dropped on the bridge, where no upstream can serve them;
the recipe disables `web_search`. Reasoning carry-over is for Responses
clients in this release.

## Get started

```bash
GEMINI_API_KEY=<key> npx babelgate --config codex-gemini.yaml
```

Recipe and all three example configs: `docs/recipes/codex.md`. babelgate is
Apache-2.0, zero-config to start: `npx babelgate`.
